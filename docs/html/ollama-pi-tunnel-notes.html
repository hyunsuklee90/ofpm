Ollama + pi operational notes

Ollama, pi, SSH Tunnel 설정 메모

GPU 서버의 Ollama를 다른 노드나 로컬 PC에서 pi와 Ollama CLI로 사용할 때 필요한 설정 요약.

1. 역할 구분

  • OLLAMA_HOST: Ollama CLI가 접속할 Ollama native API 주소.
  • ~/.pi/agent/models.json의 baseUrl: pi가 접속할 OpenAI-compatible API 주소.
  • Ollama CLI는 /api/... 계열을 쓰고, pi는 /v1/... 계열을 쓴다.
  • 모델 파일은 클라이언트 노드에 필요 없다. Ollama 서버가 모델 파일을 가지고 있으면 된다.

2. URL 규칙

용도 값 예시 비고
Ollama CLI OLLAMA_HOST=http://ollama-gpu:11434 /v1을 붙이지 않는다.
pi models.json "baseUrl": "http://ollama-gpu:11434/v1" pi가 OpenAI-compatible API로 붙기 때문에 /v1이 필요하다.
Ollama native API 확인 curl http://ollama-gpu:11434/api/tags 서버 모델 목록이 보여야 한다.

3. A/B 서버 공용 models.json

A 서버와 B GPU 서버가 같은 models.json을 공유하면, 파일 안의 URL도 두 서버에서 모두 의미가 같아야 한다.

권장: hostname alias 사용

# /etc/hosts on A
10.0.0.150 ollama-gpu

# /etc/hosts on B
127.0.0.1 ollama-gpu

공유 models.json:

{
  "providers": {
    "ollama": {
      "api": "openai-completions",
      "apiKey": "ollama",
      "baseUrl": "http://ollama-gpu:11434/v1",
      "models": [
        {
          "id": "MODEL_NAME_FROM_OLLAMA_LIST",
          "contextWindow": 131072,
          "maxTokens": 8192,
          "input": ["text"],
          "reasoning": true
        }
      ]
    }
  }
}

models.json의 baseUrl은 현재 pi 기준으로 OLLAMA_HOST 같은 환경변수를 자동 치환하지 않는다. 공용 파일을 유지하려면 DNS 또는 /etc/hosts로 hostname을 맞추는 방식이 가장 단순하다.

4. SSH 터널

로컬 PC에서 GPU 서버 Ollama를 쓰려면 SSH 터널을 열고, 로컬 포트를 OLLAMA_HOST와 pi baseUrl에 사용한다.

# ~/.ssh/config
Host ai
    HostName 10.0.0.150
    User YOUR_USER
    ProxyJump YOUR_USER@10.30.14.87:20222
    LocalForward 127.0.0.1:11435 127.0.0.1:11434
    ExitOnForwardFailure yes
    ServerAliveInterval 30
    ServerAliveCountMax 3
  • LocalForward 왼쪽 127.0.0.1:11435: 로컬 PC에서 열리는 입구.
  • LocalForward 오른쪽 127.0.0.1:11434: 원격 GPU 서버의 Ollama 포트.
  • 로컬에 Ollama가 이미 11434를 쓰고 있으면 왼쪽 포트를 11435처럼 바꾼다.
ssh -N ai
curl http://127.0.0.1:11435/api/tags
export OLLAMA_HOST=http://127.0.0.1:11435

pi models.json은 다음처럼 맞춘다.

"baseUrl": "http://127.0.0.1:11435/v1"

5. systemd user service로 터널 상시 유지

개인 사용자용이면 ~/.config/systemd/user 아래에 service를 둔다.

mkdir -p ~/.config/systemd/user
vi ~/.config/systemd/user/ollama-tunnel.service
[Unit]
Description=SSH tunnel to remote Ollama
After=network-online.target

[Service]
Type=simple
ExecStart=/usr/bin/ssh -NT -o ExitOnForwardFailure=yes ai
Restart=always
RestartSec=5

[Install]
WantedBy=default.target
systemctl --user daemon-reload
systemctl --user enable --now ollama-tunnel.service
systemctl --user status ollama-tunnel.service --no-pager

로그 확인:

journalctl --user -u ollama-tunnel.service -n 80 --no-pager
journalctl --user -u ollama-tunnel.service -f

로그인 전에도 user service를 유지하려면:

sudo loginctl enable-linger "$USER"

6. 공용 OLLAMA_HOST 설정

터미널 사용자 전체에 같은 값을 주려면 /etc/profile.d에 둔다.

sudo tee /etc/profile.d/ollama-host.sh >/dev/null <<'EOF'
export OLLAMA_HOST=http://ollama-gpu:11434
EOF

SSH 터널 포트를 쓰는 PC에서는:

export OLLAMA_HOST=http://127.0.0.1:11435

/etc/profile.d는 shell 환경용이다. systemd service에는 자동 적용되지 않는다. service에 필요하면 unit의 Environment=...를 따로 설정한다.

7. pi 설정 파일

  • 기본 pi config root: ~/.pi/agent
  • 모델 정의: ~/.pi/agent/models.json
  • 기본 provider/model: ~/.pi/agent/settings.json
  • PI_CODING_AGENT_DIR는 전체 agent config root를 바꾼다. models.json만 바꾸는 변수는 아니다.

공용 models.json만 쓰고 개인 설정은 유지하려면 symlink가 단순하다.

mkdir -p ~/.pi/agent
ln -sf /opt/ofpm/config/pi-agent/models.json ~/.pi/agent/models.json

settings.json 예시:

{
  "defaultProvider": "ollama",
  "defaultModel": "MODEL_NAME_FROM_OLLAMA_LIST",
  "packages": [],
  "hideThinkingBlock": true
}

offline 환경에서 pi가 뭔가 설치하려고 하면 settings.json의 packages를 확인한다. 필요 없으면 빈 배열로 둔다.

8. 자주 쓰는 확인 명령

# 어떤 pi가 실행되는지
type -a pi
readlink -f "$(command -v pi)"

# pi가 보는 config root 강제 확인
node --input-type=module -e "import {getAgentDir,getSettingsPath,getModelsPath} from '/home/hyunsuk/.nvm/versions/node/v24.13.1/lib/node_modules/@earendil-works/pi-coding-agent/dist/config.js'; console.log({agentDir:getAgentDir(), settings:getSettingsPath(), models:getModelsPath()});"

# 로컬 포트 충돌 확인
ss -ltnp | grep -E '11434|11435'

# 터널/API 확인
curl http://127.0.0.1:11435/api/tags
ollama list
pi --no-session --list-models

# pi를 특정 모델로 새 세션 실행
pi --no-session --provider ollama --model MODEL_NAME_FROM_OLLAMA_LIST

9. 흔한 문제

bind 127.0.0.1:11434: address already in use

  • 로컬 11434를 이미 로컬 Ollama나 다른 터널이 쓰는 상태.
  • LocalForward 왼쪽 포트를 11435 같은 빈 포트로 바꾼다.

could not request local forwarding

  • SSH가 로컬 포트를 열지 못했다는 뜻.
  • 대부분 로컬 포트 충돌이므로 ss -ltnp | grep 11434로 확인한다.
  • ExitOnForwardFailure yes를 켜서 실패 시 서비스가 명확히 실패하게 한다.

model not found

  • models.json의 id와 settings.json의 defaultModel이 실제 ollama list의 NAME과 정확히 같아야 한다.
  • pi --continue 또는 pi --resume은 예전 세션의 모델을 다시 잡을 수 있다.
  • 새 모델 확인은 pi --no-session --provider ollama --model ...로 한다.
